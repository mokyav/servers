# Koruva

ブラウザで動くオリジナルのボクセルサンドボックス。Three.js + Cloudflare Workers + Durable Objects(WebSocket)。
**ルームコードで最大8人が同じワールドに入り、ブロックの設置・破壊がリアルタイムに同期されます。**

## 起動

```bash
npm install
npm run dev          # クライアントをビルドして wrangler dev (http://localhost:8787)
```
2つのブラウザタブ(または別ブラウザ)を開き、片方で「ルームを作成」→ 表示されたコードをもう片方で「参加」。

クライアントだけ高速に開発したい場合: ターミナル1で `npx wrangler dev`、ターミナル2で `npm run dev:client`(Vite が /api と /ws を 8787 へプロキシ)。

## デプロイ

### A. コマンドライン
```bash
npx wrangler login
npm run deploy       # 型チェック → vite build → wrangler deploy
```
初回デプロイ時に Durable Object のマイグレーション(`new_sqlite_classes`)が自動適用されます。**無料プランでも動作します**(SQLite バックエンドの Durable Object)。

### B. Cloudflare ダッシュボード(Git 連携 / Workers Builds)
Workers & Pages → Create → Import a repository で GitHub リポジトリを選択し:

| 項目 | 値 |
|---|---|
| ルートディレクトリ | このプロジェクトのフォルダ(例 `koruva`) |
| ビルドコマンド | `npm run build` |
| デプロイコマンド | `npx wrangler deploy` |

Worker 名は `wrangler.jsonc` の `name` と一致させてください。

## 構成

```
shared/            クライアント・サーバー共通(ブロック定義・プロトコル型・入力検証)
src/worker/        Cloudflare Worker (index.ts) と Durable Object (room.ts)
src/client/        Three.js クライアント
  worldgen.ts      シードからの決定的な地形生成(純粋関数)
  world.ts         チャンク管理・編集差分
  mesher.ts        隠れ面カリング + 頂点AO のメッシュ生成(three 非依存)
  chunkview.ts     チャンクのロード/破棄/メッシュ化キュー、描画(フラスタムカリング)
  physics.ts       AABB 衝突・ボクセルレイキャスト
  sky.ts / atlas.ts / remote.ts / net.ts / save.ts / ui.ts / main.ts
test/              ロジックのテスト (npm test)
```

## 仕組み

- **ワールド = シード + 編集差分**。地形はシードから両クライアントで同じように生成され、サーバーは編集差分のみをチャンク単位(`c:<cx>,<cz>` → 16KBの配列)で Durable Object Storage に保存します。入室時に差分が全送信されます。
- **ブロック同期**: クライアントは楽観的に即反映 → サーバーが検証(座標範囲・ブロックID・岩盤保護・到達距離・レート制限)して全員へ `set` を配信。拒否されたら `reject` で巻き戻し。同時編集はサーバー到着順が勝ちます。
- **Hibernation API**: 操作がない間は Durable Object がメモリから退避し、課金が止まります。keep-alive は `ping`/`pong` の自動応答(起こさない)。
- **描画の効率化**: 16×16×64 のチャンク単位メッシュ / 隠れ面カリング / チャンク単位フラスタムカリング / 描画距離外の破棄 / 1フレームあたりの生成・メッシュ化数の上限 / 編集時は該当チャンク(境界なら隣も)のみ再メッシュ。
- **昼夜**: ルームではサーバー作成時刻基準で全員同じ時刻(1日=8分)。ソロは保存対象。
- **セーブ・ロード**: ソロはブラウザの localStorage(ポーズメニューのセーブ/ロード + 15秒ごとに自動保存)。ルームのワールドはサーバーに常時保存、プレイヤー位置とホットバーはブラウザに保存。

## 操作

WASD 移動 / マウス 視点 / 左 破壊 / 右 設置 / 中クリック ブロック取得 / 1–9・ホイール ホットバー / **E インベントリ** / **Enter・T チャット** / Tab プレイヤー一覧 / V 三人称(自分のスキン確認) / Space 2回 飛行(クリエイティブのみ。Space 上昇、Shift 下降)/ Shift ダッシュ / **Esc メニュー**

- 画面をクリック(または「ゲームに戻る」)でマウスがロックされ、Esc でロック解除とメニュー表示。Chrome は Esc の直後約1秒はロックを拒否するため、その間にクリックしても自動で再試行します。
- チャットは Enter で開いて Enter で送信、Esc で閉じます(日本語入力の変換確定の Enter では送信されません)。

## ゲームモード(ルーム作成時に選択)

| | クリエイティブ | サバイバル |
|---|---|---|
| 飛行 | できる | できない |
| ブロック | 無限(インベントリから選ぶ) | 壊して集める / 置くと減る |
| 破壊 | すぐ壊せる | ブロックごとの時間だけ長押し |
| 体力 | なし | ハート10個。3ブロック超の落下でダメージ、満腹度が高いと時間で回復、0で初期位置に復活 |
| 空腹 | なし | 満腹度10個。時間とダッシュで減り、0になると体力が(1まで)減っていく。食べ物はまだ無い(リスポーンで満タン) |

ソロは常にクリエイティブです。ルームのモードは作成時に選び、**ホストは `/gamemode` で後から切り替えられます**(下記)。

### アイテムのドロップ(サバイバル)

ブロックを掘ると、その場に小さな立方体の**ドロップ(エンティティ)**が出て、落下・回転します。近づいて**回収するとインベントリに入ります**。ドロップはサーバーが管理し(最大300個・5分で消滅)、早い者勝ちで全員に同期されます。クリエイティブでは出ません。

所持数が0になったアイテムは、ホットバーにもインベントリにも残りません。

## コマンド(サーバー管理者=ホスト専用)

チャット(Enter / T)で入力します。ホスト以外が使うと拒否され、他の人にはコマンドの文面も見えません。

| コマンド | 内容 |
|---|---|
| `/gamemode survival` | ルーム全体をサバイバルに変更(`s` など頭文字だけでも可) |
| `/gamemode creative` | ルーム全体をクリエイティブに変更(`c` など頭文字だけでも可) |

変更はサーバーに保存され、全員に即時反映されます。クリエイティブに切り替えるとドロップは消えます。

## 名前

- 使える文字は **半角英数字(a-z A-Z 0-9)と `_` のみ**、1〜16文字。空白・`,` `.` 記号・日本語は使えません(入力時に取り除かれ、サーバーでも検証されます)。
- **空のままでは参加できません**。
- 同じルームに同じ名前の人がいると入室できません(大文字小文字は区別しません)。

## チャット履歴

チャットを開くと、これまでの履歴(最大30件)が表示され、スクロールできます。履歴は**クライアント側(ブラウザの localStorage)にだけ保存**され、ルームごと(ソロは別枠)に分かれます。

## サーバー管理(ホスト専用)

ルームを作成した人だけが、Esc メニューに「サーバー管理」を持ちます(プレイヤーのキック / BAN、BAN の解除)。`/gamemode` コマンドもホストだけが使えます。

- ルーム作成時にサーバーが秘密のホストトークンを発行し、作成者のブラウザ(localStorage)にだけ保存します。入室時にそれを提示した接続だけがホストです。権限はサーバー側で検証されます。
- BAN は「端末ID(localStorage)」と「IPアドレス」の両方で判定し、Durable Object に保存されます(再起動後も有効)。ホスト本人は締め出されません。
- ブラウザのサイトデータを消すとホスト権限は失われます(その端末ではホストに戻れません)。

## 既知の制限・今後

- PC(キーボード+マウス)専用。タッチ操作は未対応。
- ルーム入室時に編集差分を全件送信します。大規模ワールドではチャンク単位の遅延配信が必要です。
- 編集は1操作ごとに 16KB のチャンク配列を書き込みます。負荷が増えたらアラームでまとめ書きしてください。
- 古いルームの自動削除、ルーム作成のレート制限、洞窟/バイオームは未実装です。
- 体力・満腹度・効果・食事進行はルームサーバーが管理し、クライアントから送られた体力/満腹度値は受理しません。移動・環境判定はゲームのクライアント側物理にも依存するため、改造クライアントへの完全な対策ではありません。
- ドロップはサーバーのメモリ上にだけあり、サーバーが再起動すると消えます。
- `/gamemode` はルーム全体のモードを変えます(プレイヤーごとの切り替えは未対応)。不正対策が必要なら、プレイヤーごとの所持品をサーバーで持つ必要があります。
- 同じIPを共有する人(同じ家・学校など)はBANに巻き込まれる可能性があります。
- タイトル画面でMinecraftスキンPNG（64×64、または旧形式64×32）をアップロードできます。旧形式は64×64に正規化し、左右の腕・脚を補完します。画像はブラウザに保存され、ルームでは他のプレイヤーにも共有されます。第一レイヤーの透明ピクセルは黒に変換し、第二レイヤーの透明は維持します。半透明ピクセルは不可です。
- プレイヤーのスキンは頭32×16、胴24×16、各腕・脚16×16の標準Minecraft UV配置で表示します。Three.jsのMeshBasicMaterial（Unlit相当）とNearestFilter（Point相当）、ミップマップなしでドットを維持します。
- 外部アセットは一切使っていません。テクスチャ・モデルはすべてコードで生成しています。


## Minecraft風サバイバル機能 (追加)

- ルームのVitals、効果時間、食事タイマーはDurable Objectのサーバー処理を正とし、ログイン/再接続時に保存値を正規化して復元します。hidden effect stackと食事中の残りtickも保存対象です。
- Adventureはサーバー側で通常ブロックの破壊・設置を拒否します。許可リストは `shared/vitals.ts` の `ADVENTURE_BREAK_ALLOWLIST` / `ADVENTURE_PLACE_ALLOWLIST` で拡張でき、破壊対象はサーバーが保存編集または決定的地形生成から取得します。
- `/effect give <name|@a|@s> <effectId> <seconds> <0..255>` と `/effect clear <name|@a|@s> [effectId]` はホスト専用。チャット入力でTabを押すと操作・対象・登録済み効果を補完します。強さは0がレベルIです。
- HUDは体力、追加体力、空腹度、状態効果を表示します。効果の10秒未満点滅は残り時間に応じて速くなり、登録色の3Dパーティクルを描画します。
- 現在のゲームにMob、村人、釣り、襲撃、凍結環境、酸素/水中呼吸の空気ゲージがないため、それらに依存する効果は登録/同期/描画のフックまでで、対応するゲームプレイ本体は未実装です。コンジットパワーは水中呼吸/暗視の既存フック、slow_falling・levitationはプレイヤー垂直移動に反映します。
- Durable Object alarmは厳密な20Hzクロックではありません。実時間20tick/秒の保証、ブラウザ上の受入25項目すべて、Cloudflare統合試験、完全なMob/戦闘・防具・毒など環境判定は未検証/未接続です。
